# Wi-Fi 与自己的电脑代理

这份教程面向第一次配置网络的用户。你不需要理解代理原理，只需要先判断设备能不能直连；确实不能直连时，再按顺序找到自己电脑的局域网 IP 和代理端口。

设备连接 Wi-Fi、设备访问 Muse 云端、手机绑定 Muse 账号是三个独立步骤。手机 Muse 能使用，不代表 AI Passport 会自动共用手机的网络或代理。

## 先判断：是否真的需要电脑代理

| 情况 | 电脑代理 IP | 电脑代理端口 |
| --- | --- | --- |
| 设备连接普通 Wi-Fi 后能进入 Muse，并显示“我准备好了” | 留空 | 留空 |
| 设备已连接 Wi-Fi，但持续提示域名解析、连接服务器或网络出口失败 | 按本文查找 | 按本文查找 |

建议先把两个代理输入框留空保存，打开设备 Muse 测试。能正常连接就不要配置电脑代理；多填一层代理反而会增加电脑关机、IP 变化和防火墙导致的故障。

当前固件只支持：

- IPv4 地址，例如 `192.168.50.10`；
- HTTP 代理端口或 Mixed/混合端口；
- 不需要用户名、密码的局域网代理。

当前固件不支持 SOCKS-only 端口、带用户名密码的代理、代理域名、网页控制面板端口或 External Controller/API 端口。

## 第一步：让设备和电脑处于同一局域网

1. 在 AI Passport 手机设置页，让设备连接家里或办公室的 **2.4 GHz Wi-Fi**。
2. 电脑连接同一个路由器。电脑可以使用网线、2.4 GHz 或 5 GHz；关键是电脑和设备能在局域网中互相访问。
3. 不要使用访客 Wi-Fi。部分路由器的“访客网络”“AP 隔离”“客户端隔离”会阻止设备访问电脑。
4. 使用电脑代理期间，电脑必须保持开机，Clash Verge/Mihomo 等代理软件也必须持续运行。

如果电脑连的是 A 路由器、设备连的是手机热点或 B 路由器，即使两边都能上网，设备通常也不能访问电脑代理。

## 第二步：在 Clash Verge / Mihomo 中找到代理端口

不同版本的菜单名称可能略有差异，一般在 Clash Verge 或 Mihomo 的“设置”“端口设置”或“网络设置”中。

1. 打开 Clash Verge/Mihomo。
2. 找到并开启 **允许局域网连接 / Allow LAN**。
3. 找到 **Mixed Port / 混合端口** 或 **HTTP Port / HTTP 端口**。
4. 记下端口数字，例如 `7890`、`7897` 或 `7900`。这只是示例，必须以你电脑实际显示的数字为准。

不要选择 SOCKS 端口、External Controller/API 控制端口、Web UI/Dashboard 管理端口，也不要直接照抄别人机器的端口。

### 用 PowerShell 确认端口是否正在监听

右键 Windows 开始菜单，打开“终端”或“PowerShell”。把下面的 `7900` 换成代理软件里看到的端口：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 7900 |
  Select-Object LocalAddress, LocalPort
```

| PowerShell 结果 | 含义 |
| --- | --- |
| `0.0.0.0  7900` 或 `::  7900` | 正常：代理在所有网卡监听，局域网设备有机会连接 |
| 只有 `127.0.0.1  7900` | 只能电脑自己访问；回到代理软件开启 Allow LAN |
| 没有任何输出 | 端口填错、代理没启动，或该端口没有监听 |

## 第三步：查看电脑的局域网 IPv4

仍在 PowerShell 中复制并运行：

```powershell
Get-NetIPConfiguration |
  Where-Object IPv4DefaultGateway |
  Select-Object InterfaceAlias,
    @{Name="电脑局域网IP";Expression={$_.IPv4Address.IPAddress}}
```

你可能会看到类似结果：

```text
InterfaceAlias 电脑局域网IP
-------------- ------------
以太网         192.168.50.11
Mihomo         198.18.0.1
WLAN           {192.168.50.10, 169.254.242.248}
```

选择规则：

1. 设备通过家里 Wi-Fi 联网时，优先选择 `WLAN` 或 `Wi-Fi` 行中的 `192.168.*.*`、`10.*.*.*` 或 `172.16.*.*`–`172.31.*.*` 地址。
2. 电脑只通过网线连接同一个路由器时，选择“以太网”行的局域网地址。
3. 如果 WLAN 一行同时出现多个地址，例如 `{192.168.50.10, 169.254.242.248}`，选择 `192.168.50.10`。
4. 电脑同时连网线和 Wi-Fi，而且两者都属于同一个路由器时，优先选择设备所在 Wi-Fi 对应的 WLAN 地址；不通时再尝试以太网地址。

以下地址不要填写：

| 地址 | 为什么不能填 |
| --- | --- |
| `127.0.0.1` | 表示 AI Passport 自己，不是你的电脑 |
| `198.18.*.*` | 常见于 Mihomo/Clash 的 TUN 虚拟网卡，不是设备可访问的真实局域网地址 |
| `169.254.*.*` | Windows 没有正常获得网络地址时生成的临时地址 |
| WSL、Docker、VMware、Hyper-V 的地址 | 虚拟网络地址，普通 Wi-Fi 设备通常无法访问 |
| 公网 IP | 不需要也不应该把代理暴露到公网 |

也可以从 Windows 图形界面查看：**设置 → 网络和 Internet → Wi-Fi（或以太网）→ 当前连接的网络 → 硬件属性 → IPv4 地址**。

## 第四步：组合并验证自己的代理地址

假设你查到电脑 WLAN IPv4 是 `192.168.50.10`，Mihomo Mixed Port 是 `7900`，那么代理就是 `192.168.50.10:7900`。不要把这组示例原样复制到别人的网络。

在 PowerShell 中测试端口，把变量换成自己的实际值：

```powershell
$proxyIp = "192.168.50.10"
$proxyPort = 7900

Test-NetConnection $proxyIp -Port $proxyPort
curl.exe --proxy "http://${proxyIp}:$proxyPort" `
  --connect-timeout 10 --max-time 20 -I https://hatch.metaaivm.com/
```

- `TcpTestSucceeded : True`：电脑上的端口正在响应；继续检查设备配置。
- “连接被拒绝”：端口不对、代理没运行，或 Allow LAN 没开启。
- “连接超时”：先检查 IP、访客网络隔离和 Windows 防火墙。
- curl 收到目标网站的 HTTP 响应，包括根路径的 `404` 或 `405`：代理 CONNECT 与 TLS 链路已经到达目标服务器。
- `407 Proxy Authentication Required`：代理要求账号密码，当前固件不能使用。
- `502`、`503` 或解析失败：代理端口可以连接，但代理出口或 DNS 仍有问题。

不要给 curl 增加 `-k`，也不要关闭 TLS 验证。

## 第五步：填写到 AI Passport

1. 从设备首页长按下键进入手机设置；也可从“设置 → 手机设置”进入。
2. 手机连接设备屏幕显示的热点。手机提示“没有互联网”时，仍然保持连接。
3. 浏览器打开设备屏幕显示的地址，通常是 `192.168.4.1`。
4. 在页面选择设备要使用的 2.4 GHz Wi-Fi，并填写 Wi-Fi 密码。
5. 打开“个人资料 → Muse 语音助手”。
6. “电脑代理 IP”只填 IP，例如 `192.168.50.10`，不要写 `http://`，也不要在后面加冒号或端口。
7. “电脑代理端口”只填数字，例如 `7900`。
8. 填写本人 Muse SDK Token，点击“保存 Muse 配置”，再完成整个设置页面。
9. 让手机退出设备热点、恢复正常联网；设备也应回到刚才选择的 Wi-Fi。
10. 打开设备 Muse，等待“我准备好了”，再实际发送一条语音并查看文字回复。

正确填写：

```text
电脑代理 IP：192.168.50.10
电脑代理端口：7900
```

不要把 `http://192.168.50.10:7900` 全部塞进 IP 输入框。已有 Token 时，Token 输入框留空表示保留原值；只修改代理不会自动解除 Muse 配对。

## Windows 防火墙怎么处理

第一次开启 Allow LAN 或首次运行代理时，Windows 可能询问是否允许网络访问：

1. 只勾选“专用网络”，不要向公共网络开放。
2. 允许 Clash Verge/Mihomo 通过 Windows 防火墙。
3. 不要为了排查问题直接关闭整个防火墙。

如果没有出现提示，可进入 **Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙**，确认 Clash Verge/Mihomo 在“专用”网络下被允许。公司网络或受管电脑可能不允许修改规则，需要联系网络管理员。

## IP 改变、电脑休眠和手机热点

电脑重连 Wi-Fi、路由器重启或更换网络后，局域网 IP 可能改变。Muse 再次连接失败时，重新运行本文的 IP 查询命令并更新设备设置。可在自己的路由器中为电脑设置 DHCP 地址保留，减少 IP 变化。

电脑休眠、关机或退出代理软件后，设备无法继续通过电脑代理访问 Muse，但通常不需要清除账号配对。

手机热点、手机 VPN 是否能把网络共享给 ESP32，取决于手机系统和软件能力。手机自己能访问 Muse，不代表热点下的设备会自动继承手机 VPN；最终必须以设备真正显示就绪并收到回复为准。

## 按现象排查

| 现象 | 优先检查 |
| --- | --- |
| 手机打不开设备设置页 | 手机是否仍连接设备热点；是否打开屏幕地址；手机是否自动切回有互联网的 Wi-Fi |
| 设备连不上 Wi-Fi | 是否为 2.4 GHz；密码是否正确；信号是否足够；是否使用访客网络 |
| PowerShell 查不到代理端口 | 代理是否运行；端口是否抄对；是否误看成控制端口 |
| 端口只监听 `127.0.0.1` | 开启 Allow LAN，然后重新检查监听地址 |
| 代理连接失败 | IP、端口、Allow LAN、防火墙、访客网络隔离、电脑休眠 |
| 域名解析失败 | 先检查代理出口和 DNS；保存正确代理后退出并重新打开 Muse |
| 手机能配对，但设备未显示“我准备好了” | 配对成功不等于设备云端网络可达，继续检查代理链路 |
| 手机找不到设备 | 先在硬件打开 Muse；打开手机 Muse 开发者模式；不要在系统蓝牙设置中添加 |
| 语音已发送但硬件没有结果 | 保持 Muse 页面等待最终回复；不要按下键取消；记录脱敏后的错误阶段 |

不要因为一次网络超时就全盘擦除或反复清除配对。反馈问题时删除 Token、配对材料、个人网络名称、代理订阅和对话内容。

## 仍然提示“域名解析失败”

在 Windows PowerShell 执行：

```powershell
Resolve-DnsName hatch.metaaivm.com
```

- 返回 IP：只证明电脑 DNS 能解析，不代表 AI Passport 整条链路已经正常。
- 超时或找不到域名：先修复电脑/代理使用的 DNS 与网络出口。
- 电脑能解析但设备仍失败：确认设备和电脑在同一路由器、没有客户端隔离，并重新核对设备中保存的 IP 和端口。

电脑自测成功仍不能代替设备验收。最终标准始终是：设备显示“我准备好了”，可以真实提交语音并收到相关文字回复。
