# Wi-Fi 与自己的电脑代理

设备连接Wi-Fi、设备访问Muse云端、手机绑定账号是三个步骤。手机Muse能使用，不代表ESP32拥有相同网络通道。

## 选择哪种方式

| 方式 | 填写内容 | 依赖 |
| --- | --- | --- |
| Wi-Fi/路由器可直接让设备访问Muse | 代理IP与端口留空 | 设备自己的网络 |
| 通过自己的电脑HTTP代理 | 电脑局域网IPv4和HTTP/混合端口 | 电脑开机、代理运行、局域网互通 |

当前实现只支持IPv4 HTTP CONNECT代理，无代理用户名密码、SOCKS-only或域名输入支持。HTTPS、授权刷新和实时连接走同一配置，保留Muse服务器TLS证书验证。代理端处理目标域名解析。不要填写代理管理面板端口。

## Windows 与 Clash / Mihomo 示例

1. 电脑先确认自己的Muse能正常使用，代理也有可用网络出口。
2. 在代理软件开启“允许局域网 / Allow LAN”。HTTP或混合端口以自己设置为准，不能直接照搬别人机器的7897或7890。
3. Windows“设置 → 网络和Internet → 当前Wi-Fi/以太网 → 属性”查看IPv4地址。也可在PowerShell输入 `ipconfig`，找正在连接该网络的适配器。不要选择VPN、WSL、Docker或已断开的适配器。
4. 设备与电脑连接可互通的同一局域网。电脑可以用网线、设备用Wi-Fi，但访客网络/客户端隔离可能阻止互通。
5. 防火墙仅向自己的可信局域网开放所需TCP端口，不要关闭整套防火墙。代理也应限制允许访问的范围，避免开放到公网。操作可能需要管理员确认。
6. 手机设置页填写电脑IPv4，例如 `192.168.1.10`，以及自己的HTTP/混合端口，保存并重新打开设备Muse。

`127.0.0.1` 是设备自身，不能指向电脑。此仓库默认代理为空，不会连接作者电脑。

配置参考 [Mihomo官方局域网说明](https://wiki.metacubex.one/config/general/#允许局域网)。已有代理若要求用户名密码，当前固件不能直接使用；可以在受控局域网另设符合软件能力的访问方式，不能把有认证的地址当无认证地址填写。

## IP改变、电脑休眠、手机热点

电脑IP改变后需要更新硬件配置。可在路由器设置DHCP地址保留；在电脑保持服务运行期间避免自动睡眠。关闭代理或电脑后，设备会断开Muse，但不应因此清除账号配对。

手机热点、手机VPN或网络工具是否能把网络提供给ESP32，取决于系统与工具的共享能力。不要只验证手机自身能访问；应完成设备端连接及真实发送。手机蓝牙配对不承担当前固件的联网转发。

## 按层排查

| 现象 | 先检查 |
| --- | --- |
| 手机配网页打不开 | 是否仍连接设备热点；是否打开屏幕地址；是否自动切回互联网Wi-Fi |
| 硬件Wi-Fi未连接 | 2.4GHz、密码、信号和路由器设置 |
| 手机能配对，硬件云端未连通 | 从设备到Muse的网络出口，不要反复清空授权 |
| 代理连接失败 | IPv4、端口、Allow LAN、防火墙、访客网络隔离、电脑休眠 |
| 服务器域名解析失败 | 直连网络的 DNS/可达性；代理模式也检查代理本身的 DNS/出口，保存后重开 Muse |
| 账号授权失效 | 用户自己的账号/Token/授权状态；必要时重新配对 |
| 手机找不到设备 | 先打开设备Muse；手机权限与开发者模式；已有配对时设备不再广播 |
| 等待配对却不能完成 | 在Muse App添加，而不是系统蓝牙设置；确认硬件是否出现实体确认 |
| 语音收到但硬件没结果 | 等待最终回复并保持页面；不要按下键取消同步；检查实际日志错误 |

不要因为网络超时就直接全盘擦除。反馈时日志应删除凭据、个人网络名称和对话内容。

## 保存后仍失败：逐层检查

退出 Muse，确认设备连接自己的路由器而不是设置热点。重新查电脑当前 IPv4 和代理 HTTP/混合端口，示例地址不能原样复制。电脑 5 GHz、设备 2.4 GHz 并不一定有问题，关键是局域网能否互通。

核对 Allow LAN 和仅限可信局域网的入站规则。填写硬件手机设置页时，已有 Token 留空保留，保存代理后完成设置，再进入 Muse。不要填 SOCKS-only、管理 API 或网页面板端口。

若已就绪却发送后断开，记录固件版本和错误阶段；内存不足、远端异常与网络中断需要分别诊断，不要盲目重配账号。本项目不提供共享代理，不要求关闭防火墙。

## “域名解析失败”的最小诊断

以下在 Windows PowerShell 执行，不需要填写 Token。当前源码的实时连接默认域名为 `hatch.metaaivm.com`；如果脱敏日志中的失败目标不同，应改查日志里的域名，不要把账号、URL 查询参数或授权头贴出来。

```powershell
Resolve-DnsName hatch.metaaivm.com
```

- 返回 IP：只证明电脑使用的 DNS 能解析，不证明设备 DNS、代理 DNS、账号授权或整条 Muse 链路正常。
- 报超时/找不到域名：先检查电脑当前网络和路由器 DNS，再换一个允许设备访问的可信网络对照。不要给固件硬编码临时解析出的 IP，服务地址可能变化。
- 手机能访问、电脑能解析但设备仍失败：确认设备确实连同一路由器、没有访客隔离；退出手机设置模式后重新打开 Muse。直连网络无法访问时，再按前文配置自己的代理。

代理模式先测试自己的监听端口。把示例 IP 和端口替换成自己的实际配置：

```powershell
Test-NetConnection 192.168.1.10 -Port 7897
curl.exe --proxy http://192.168.1.10:7897 --connect-timeout 10 --max-time 20 -I https://hatch.metaaivm.com/
```

`TcpTestSucceeded: True` 仅证明执行命令的电脑到该端口可达。curl 成功建立代理 CONNECT 和 TLS 后，收到目标站点 HTTP 响应（例如根路径的 404/405），才说明这次链路已到目标服务器，不代表已完成 Muse 会话。代理自身返回的响应不能算目标站点响应：407 表示代理需要认证，当前固件不支持；连接被拒绝/超时先查监听、Allow LAN 与防火墙，502/503 或解析错误再查代理出口。不要加 `-k` 跳过 TLS 校验。

在代理电脑上自测成功仍不证明硬件可达：最终标准始终是设备显示就绪、真实提交语音并收到文字回复。检查后保存正确配置，再按确定重试；无需先清空配对。
